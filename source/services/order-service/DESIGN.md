# Order Service

Owns orders and item price snapshots. Creation checks each item against Catalog over REST before the local transaction; POS orders start `AWAITING_CASH`, while pickup/delivery orders start `CONFIRMED` with `PENDING_CASH`. The order amount cannot be edited after creation. Cash confirmation reads Payment's receipt over REST before a conditional local update; a duplicate confirmation with the same payment ID is safe. Paid cancellation requires `order:approve_cancel` and moves to `REFUND_PENDING`; Order verifies Payment's refund receipt before `REFUNDED`. Every state change writes a local outbox row. Cross-service confirmation failure returns a pending result from Payment for retry. Automatic voucher/point and inventory orchestration is not yet present. Local standalone configuration and deployment are in `source/services/order-service/.env.example` and `compose.yml`; integrated configuration is in `source/.env.example` and `source/compose-business.yml`.
